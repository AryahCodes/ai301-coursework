# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| plan-fidelity | Issue request and thread directions; plan-context scope, files, approach and deviations paired with every diff hunk (guide: Plan fidelity) | The diff implements the issue's claimed behavior within the plan's boundary. Every material addition, omission, or changed approach is either consistent with that boundary or explicitly disclosed with its reason and remaining work in plan deviations or PR text. An honest bounded partial result can pass; an undisclosed expansion or shortfall fails. Disclosure cannot excuse unrelated work or contradict an explicit maintainer requirement. | required |
| claims-match-change | PR title and description paired with diff and test-evidence results (guide: Plan fidelity and Test evidence) | Each substantive claim about behavior, scope, completeness, or verification is supported by the diff and recorded evidence. Stated limitations remain limitations, not implied successes. Claims of unchanged scope, complete implementation, or passing checks fail when the artifacts contradict them. | required |
| observable-proof | Plan's test plan and reproduction steps paired with candidate test-evidence before/after, regression tests, commands and outcomes (guide: Test evidence) | Evidence identifies an actual command or executable test, its observed result, and the expected fixed behavior for the reported failure. At least one result exercises the original failing path or an equivalent regression, with a before/control or assertion that would distinguish the bug. Generic "tests pass", proposed tests, and unevidenced assurances fail. A clearly disclosed untested edge does not fail when the claimed fix itself is exercised. | required |
| repo-checks | Repo-facts prescribed checks, plan test commands, test-evidence outputs and PR Testing section (guide: Test evidence) | Applicable repository checks have recorded commands and outcomes, or a specific disclosed reason a check could not run with its verification gap stated. No failed or unrun check is claimed as passing. A known failure in the changed behavior fails; a disclosed external blocker or bounded untested environment can pass if observable proof supports the claimed fix and no stated repository rule makes that result mandatory before submission. A passing targeted test alone does not substitute for omitted repository checks without explanation. | required |
| reviewable-diff | Complete unified diff, changed-file list and commit list paired with plan scope (guide: Diff quality) | The fix and its tests are visible without unrelated hunks, mass formatting churn, generated debris, debug prints, dead code, commented-out experiments, or accidental local files riding along. Necessary fixture, lockfile, documentation or formatting changes tied to the fix pass. Commit count and diff length alone never fail. | required |
| repo-standards | Repo-facts PR-template asks and contribution/AI-use policy, issue thread directions, candidate title/description/commits/diff (guide: Standards and comms) | All explicitly applicable requirements are satisfied: requested template content has substantive answers or justified N/A, the issue is linked as required, naming and commit rules are followed where stated, and required AI disclosure names the tool and extent of help. Explicit maintainer directions are followed or addressed with a reason. Boilerplate, a missing required section/disclosure, or an unmet binding check fails. Do not invent unstated requirements or require exact headings when equivalent content satisfies the stated ask. | required |
| limitation-clarity | PR Notes/limitations paired with plan risks and test gaps (guide: Standards and comms) | Material known limitations and remaining work are easy for a reviewer to locate and distinguish from verified behavior. | preferred |

## Verdict rule

Accept only when every required check is pass. Reject if any required check is fail or unclear. Unclear counts as fail for required checks; preferred grades never affect the binary verdict. Missing decisive evidence is fail when the pass condition requires its presence, and unclear when the available facts cannot resolve the condition. An absence explicitly allowed by a check passes with that absence cited. No score, majority vote, or intuition overrides this rule.
